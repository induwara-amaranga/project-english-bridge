Englisher Production Deployment Plan

2 October 2026 · induwara · revised: Heroku + Cloudflare Pages replace the DigitalOcean droplet

Summary

Hosting: the API and its database run on Heroku, paid for by the GitHub Student Developer Pack credit ($13/month for 24 months). The React app runs on Cloudflare Pages, which is free. The droplet plan was dropped because the DigitalOcean offer is no longer in the Student Pack.

Architecture in one line: the app is served from englisher.lk on Cloudflare Pages and calls the API at api.englisher.lk. That's a Spring Boot container on a Heroku web dyno, behind Heroku's router, connected to Heroku Postgres. There are no servers to patch, firewall or SSH into.

CI/CD in one line: push to main → tests run → the backend image is pushed to Heroku's registry and released → the workflow waits for the API to report healthy → the frontend is built and published to Cloudflare Pages.

Cost: $12/month of Heroku usage (Basic dyno $7 + Postgres Essential-0 $5) against the $13 credit, so $0 out of pocket for 24 months. A custom domain is required and is a separate cost.

Architecture

Two providers, two subdomains of one domain:

PieceRoleReachable from
Cloudflare Pages (englisher.lk)Serves the built React app, applies security headers from public/_headers, falls back to index.html for client-side routes, owns the frontend's TLS certificateInternet
Heroku router (api.englisher.lk)Heroku's built-in reverse proxy: terminates TLS (Heroku ACM certificate), forwards to the dyno's $PORT, appends X-Forwarded-ForInternet
Web dyno (Spring Boot)The API: JWT auth, curriculum, admin, OAuth verification, server-side grading, per-IP rate limiting on sign-inOnly through the Heroku router
Heroku Postgres Essential-0All persistent data, with nightly PGBackups snapshotsThe dyno, over SSL, via DATABASE_URL
SMTP relayAdmin sign-in OTPs and parent invitations. Mailpit is for local development onlyOutbound from the dyno

Request flow: the browser loads the app from https://englisher.lk, and the app calls https://api.englisher.lk/api/... with credentials: 'include'. The refresh token is an httpOnly SameSite=Lax cookie, so the app and the API must share the same registrable domain. The default *.pages.dev and *.herokuapp.com addresses would sign users out on every reload. ENGLISHER_ALLOWED_ORIGINS allows credentialed CORS from the frontend origin only.

Heroku doesn't run Docker Compose. server/docker-compose.yml remains the local development stack, and the production-only overlay was removed. This is still a single dyno, which is fine for launch. The backlog covers what to change before scaling out.

Launch plan

1. Accounts and domain

  • Claim the Heroku student credit through the GitHub Student Developer Pack and add a card (Heroku requires one even when the credit covers everything).
  • Install the Heroku CLI and run heroku login.
  • Add the domain to Cloudflare and switch its nameservers at the registrar. Propagation can take hours, so do this first.
  • Set up a real SMTP relay (Brevo, Mailgun, SES, Postmark…) with SPF/DKIM for the domain.

2. Heroku

  • Copy infra/heroku.env.example to infra/heroku.env (gitignored) and fill it in: ENGLISHER_JWT_SECRET (openssl rand -base64 32), admin email/password, SMTP credentials, ENGLISHER_ALLOWED_ORIGINS=https://englisher.lk.
  • Run bash infra/heroku-setup.sh englisher-api api.englisher.lk.
  • In Cloudflare DNS, add CNAME api → <DNS target the script printed> with the proxy off (grey cloud), so Heroku can issue the certificate.

3. Cloudflare Pages

  • Workers & Pages → Create → Pages → Direct Upload. Create the project (e.g. englisher).
  • Add englisher.lk under the project's Custom domains.

4. GitHub

  • Add the secrets and variables from the table above.
  • Commit the staged changes and push to main. Watch the Actions tab: tests → Heroku release → readiness → Pages publish should all go green.

5. After the first deploy

  • heroku ps:type web=basic -a englisher-api (Basic doesn't sleep. Eco would cold-start after 30 idle minutes).
  • heroku certs:auto:enable -a englisher-api for the api certificate.
  • Confirm https://englisher.lk loads, sign-in works, and the session survives a page reload (that proves the cookie setup).
  • Sign in as the seeded admin and confirm the 2FA OTP email arrives.
  • Run through the security checklist below.

Security checklist

Already true of this codebase:

  • Non-root user inside the backend container.
  • No default JWT secret or admin password. The app refuses to boot, or skips seeding, rather than falling back to a known value.
  • cookie-secure: true and Swagger/OpenAPI disabled under the prod Spring profile.
  • OAuth tokens (Google/Facebook) verified server-side against the provider.
  • Admin accounts have 2FA.
  • Lessons are graded server-side, and XP is paid only for exercises answered correctly. A client can't claim XP for wrong answers.
  • Sign-in, OTP and social sign-in are limited to 10 requests per minute per IP, and signup to 5 per hour. The client IP is read from the trusted right end of X-Forwarded-For, so a client can't spoof it.

Handled by the platforms:

  • TLS on both hosts: Cloudflare for the app, Heroku ACM for the API. HSTS and security headers via _headers and Spring Security.
  • Postgres isn't on any network you manage, and connections require SSL.
  • OS patching, firewalling and SSH are no longer your job. No SSH access exists to harden.

Still on you:

  • ENGLISHER_ALLOWED_ORIGINS set to the real frontend origin only (not *, not localhost).
  • Secrets live only in Heroku config vars, infra/heroku.env on your machine (never committed) and GitHub Actions secrets.
  • Keep the API's DNS record DNS-only. If you later turn on the Cloudflare proxy for api, set ENGLISHER_TRUSTED_PROXY_HOPS=2, or every request will appear to come from Cloudflare's IP.
  • Watch the Heroku billing page. Anything beyond the $13/month credit (a bigger dyno, the Key-Value Store, a second dyno) is charged to your card.
  • Turn on Dependabot alerts (Settings → Code security) for frontend/app and server/pom.xml.

Rollback & incident response

A bad API deploy: the workflow fails if readiness doesn't come up, and the frontend isn't published. To return to the previous release:

heroku releases -a englisher-api            # find the last good version
heroku releases:rollback v42 -a englisher-api

A bad frontend deploy: Cloudflare dashboard → the Pages project → Deployments → pick an earlier deployment → Rollback.

Checking logs:

heroku logs --tail -a englisher-api
heroku ps -a englisher-api                  # dyno state, restarts, memory (R14) errors

Database backups are automated: heroku-setup.sh schedules a nightly snapshot at 02:00 Sri Lanka time, and the Essential tier keeps about a week of them. Before risky changes, and now and then to keep a copy outside Heroku:

bash infra/backup-db.sh englisher-api       # capture + download to infra/backups/
heroku pg:backups -a englisher-api          # list snapshots

Restoring (puts the app in maintenance mode while it runs):

bash infra/restore-db.sh englisher-api b012                                  # a Heroku snapshot
bash infra/restore-db.sh englisher-api infra/backups/englisher-<stamp>.dump # a local copy

Backlog, worth doing once the site is live and stable:

  • Uptime monitoring (UptimeRobot or similar, free) on https://api.englisher.lk/actuator/health/readiness.
  • Automate an off-Heroku backup copy (for example a scheduled GitHub Action that downloads the latest snapshot to Cloudflare R2), so losing the Heroku account doesn't mean losing the data.
  • Before running more than one dyno: move the rate-limit counters to a shared store, since they're currently in memory per dyno.
  • Upgrade to a Standard Postgres plan if point-in-time recovery becomes important. Essential-tier plans only have daily snapshots.
  • Plan for month 25: when the credit ends, either pay about $12/month or move to another host.
